# #11 금융 교육 콘텐츠 — 소비 데이터로 배우는 개인 맞춤 금융 리터러시

## ① 개요

PayWise의 금융 교육 콘텐츠 기능은 단순한 읽기 자료 제공을 넘어, 사용자의 **실제 소비 데이터를 기반으로 학습 레벨을 배정하고, 퀴즈·챌린지·시뮬레이션을 통해 행동 변화까지 유도**하는 참여형 교육 플랫폼이다. ML 모델(XGBoost, K-Means, IsolationForest)이 진단을 담당하고, 5개 모듈이 유기적으로 연결되어 "진단 → 학습 → 실천 → 경쟁"의 학습 사이클을 구성한다.

## ③ 동작 흐름

전체 학습 사이클을 기준으로 정리한다.

```
1. 진단 요청 (GET /diagnosis/{user_id})
   └─ SpendProfile 조회 → K-Means 소비 유형 예측 → XGBoost 위험 점수 계산
      → IsolationForest 이상 거래 탐지 → DiagnosisReport 반환

2. 커리큘럼 배정 (GET /curriculum/{user_id})
   └─ 진단 결과의 risk_score + cluster_label → EduLevel(BEGINNER/INTERMEDIATE/ADVANCED) 매핑
      → 해당 레벨 4개 코스 목록 + DB 완료 이력 조회 → CurriculumAssignment 반환

3. 코스 학습 (POST /course/{course_id}/progress)
   └─ advance_course_step(): current_step + 1 → 마지막 스텝 도달 시 completed = True
      → 코스 완료 배지 자동 수여 → _update_leaderboard() 포인트 재계산

4. 퀴즈 응시 (POST /quiz/fraud → POST /quiz/fraud/submit)
   └─ 10개 시나리오에서 random.sample → FraudQuizQuestion 반환
      → 제출 시 save_quiz_score() → leaderboard 포인트 업데이트

5. 챌린지 참여 (POST /challenge/{challenge_id}/enroll)
   └─ DB에 ChallengeEnrollment 생성 (start_date, end_date = now + duration_days)
      → POST /user-challenges/{user_id}/sync: 소비 트랜잭션 기반 진행률 자동 계산
      → progress_pct >= 100 시 챌린지 완료 배지 수여

6. 시뮬레이션 (POST /simulate/fraud)
   └─ 사용자 입력값(금액, 시간, 해외 IP 여부 등)에 규칙 엔진 적용
      → rules_triggered 목록 + 최종 판정(PASS/SOFT_REVIEW/REVIEW/BLOCK) 반환
```

### 4-5. 챌린지 메트릭 계산기 (`_compute_metric`)

챌린지 유형별로 "달성값"을 계산하는 전략 함수다.

```python
# education_store_db.py:256-313
def _compute_metric(target_metric, enrollment, tx_rows, quiz_rows, now, session):
    if target_metric == "food_cafe_reduction":
        # 등록 전달 대비 식비 감소율(%)
        before = sum(r.amount for r in tx_rows if r.category in ("food", "cafe") and prev_month <= r.timestamp < start)
        after  = sum(r.amount for r in tx_rows if r.category in ("food", "cafe") and r.timestamp >= start)
        return round(max((before - after) / before * 100, 0), 1)

    elif target_metric == "zero_spend_days":
        # 챌린지 기간 내 무지출 일수
        spend_days = {r.timestamp.date() for r in tx_rows if start <= r.timestamp <= end}
        return float(max(total_days - len(spend_days), 0))

    elif target_metric == "fraud_quiz_streak":
        # 퀴즈 60점 이상 연속 달성 최대 streak
        streak, best = 0, 0
        for q in quiz_rows:
            streak = streak + 1 if q.score >= 60 else 0
            best = max(best, streak)
        return float(best)

    elif target_metric == "cluster_change":
        return None  # 소비 유형 변화는 자동 계산 불가 → 수동 유지
```

[education_store_db.py](backend/app/services/education_store_db.py:256)

`cluster_change` 메트릭에서 `None`을 반환하는 것이 눈에 띈다. K-Means 예측값 자체는 얻을 수 있지만, "이전 군집"을 기준점으로 삼으려면 별도의 스냅샷이 필요하기 때문에 자동 계산 대신 수동 진행률을 유지하도록 명시적으로 처리했다.

## ⑤ 설계 포인트 / 트러블슈팅 거리

- **정적 콘텐츠와 동적 상태의 분리**: `education_store.py`는 코스·챌린지 정의를 Python 딕셔너리로 관리하고, `education_store_db.py`는 사용자별 진행 상태만 DB에 저장한다. 콘텐츠 수정(코스 추가·변경)이 DB 마이그레이션 없이 Python 파일 수정만으로 가능한 이유이기도 하지만, 반대로 DB의 `course_id`가 Python 딕셔너리 키에 의존하므로 키 이름을 바꾸면 기존 진행 데이터가 고아(orphan)가 된다.

- **ML 모델 재사용과 진단 응답 지연**: 진단 엔드포인트 한 번에 K-Means, XGBoost, IsolationForest 세 모델이 동기적으로 호출된다. 각 모델이 인메모리 추론이라 실제 부담은 작지만, 트랜잭션 전체를 불러와 이상 탐지를 수행하는 부분(`tx_dicts` 전체 순회)은 거래 건수가 많아질수록 응답 지연 요인이 된다.

- **`cluster_change` 챌린지의 수동 진행**: 소비 유형 변화(`cluster_change`)는 자동 계산이 불가능해 `_compute_metric`에서 `None`을 반환한다. 현재는 수동 업데이트에 의존하는데, 진단 시점의 군집 레이블을 DB에 스냅샷으로 저장해두면 이후 싱크 시 변화 여부를 자동 감지할 수 있다.

- **퀴즈 제출 채점 로직의 허점**: `submit_fraud_quiz`의 채점 코드(`correct = len([a for a in answers if a == "의심 거래" or a == "정상 거래"])`)가 실제로는 모든 답변이 유효 문자열이면 무조건 correct로 카운트된다. 제출한 답변을 원본 질문과 대조하는 로직이 없어, 정답 여부를 검증하지 않는 버그가 있다. (✅ ROADMAP W9-#1 — `_fraud_correct_answer_map` 으로 question_id↔정답 대조)

- **리더보드 캐시 무효화 부재**: 퀴즈 점수나 배지 수여 후 `_update_leaderboard()`가 DB를 upsert하지만, Redis 캐시 키(`leaderboard:top`)는 TTL이 만료될 때까지 갱신되지 않는다. 쓰기 직후 캐시를 삭제(invalidate)하거나 TTL을 짧게 조정하지 않으면 리더보드가 오래된 데이터를 노출한다.

### 예상 질문 & 답변 (발표 Q&A 대비)

**Q1. ML 진단 결과가 학습 레벨에 어떻게 매핑되나요?**
> XGBoost 과소비 점수 + K-Means 소비 유형 + IF 이상 점수의 조합으로 초급/중급/고급 코스 자동 배정. 예: 과소비 위험 높은 절약형 사용자 → "예산 관리 기초" 초급, 균형형 + 이상치 적음 → "투자 입문" 중급.

**Q2. 단순 정보 제공 콘텐츠와 차별점은?**
> ① ML 기반 개인화 진단 → 레벨 자동 배정, ② 퀴즈·챌린지로 실천 유도, ③ 시뮬레이션으로 가상 의사결정 학습, ④ 리더보드로 동기 부여. 진단→학습→실천→경쟁 4단계 사이클이 핵심.

**Q3. 콘텐츠는 누가 작성하나요? 자동 생성?**
> 현재는 정적 콘텐츠(`COURSES`, `CHALLENGES`, `SPENDING_QUIZ_BANK`). LLM 기반 동적 콘텐츠 생성은 발표 슬라이드 8 "향후 계획"의 "맞춤 소비 코칭" 항목으로 정리.

**Q4. 리더보드가 오래된 데이터를 보여주는 적이 있나요?**
> ⑤절 지적대로 현재 Redis 캐시 무효화가 미흡 — 퀴즈 점수 갱신 후 캐시 TTL 만료 전엔 옛 데이터 노출 가능. 쓰기 직후 invalidate 또는 짧은 TTL이 후속 수정.

**Q5. 챌린지 부정행위(가짜 거래로 배지 획득)는 어떻게 막나요?**
> 현재는 PayWise 거래 데이터를 단일 소스로 보므로 사용자가 자기 거래를 위조하면 검출 어려움. 향후 MyData 실 연동 시 제3자 데이터 교차 검증으로 해결 가능.

## ⑥ 한 줄 정리

사용자의 실제 소비 기록을 ML로 진단해 학습 레벨을 자동 배정하고, 코스·퀴즈·챌린지·시뮬레이션이 "배우고 → 실천하고 → 경쟁하는" 한 사이클을 구성하는 참여형 금융 교육 플랫폼이다.
